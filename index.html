How it works

VoIP call flow — SIP, RTP and the dial plan

An IP desk phone is a small computer: when a call starts it sends a SIP message to the call server, which decides whether the number is an internal extension, a department ring group or an outside line — then routes the call and tells both phones where to send their audio.

SIP · RTP · PJSIP channels · Dial plan

Dalmia Bros. — 30+ endpoint rollout

How it works

Handsets that configure themselves

DHCP options 66 and 150 are the mechanism: a new handset asks for an address, and those two options tell it where to fetch its configuration file from. QoS then marks voice packets so the switch forwards them ahead of ordinary file and web traffic when the link gets busy.

DHCP 66 / 150 · Voice VLAN · QoS

TDI Bhikaji Cama Place — IP telephony rollout

How it works

Cameras over PoE, on their own segment

A PoE switch sends power and data down one cable, so each camera needs a single outlet instead of a data point plus a power socket. Because an IP camera records digitally and sends video over the network, live view and remote playback work from a browser or a phone.

PoE · IP CCTV · Segmentation · Enterprise Wi-Fi

How it works

Asterisk in place of the hardware exchange

Asterisk is software that replaces a phone exchange: PJSIP channels manage registered handsets, RTP carries the audio, and the dial plan decides where a dialled number goes. Fail2ban watches the auth log for repeated failed SIP logins and blocks those addresses.

Asterisk · Rocky Linux · Fail2ban · Kernel tuning

Backups that are restored, not just written

The 3-2-1 rule is a shape rather than a product: three copies, two media types, one kept off site. Scheduling matters more than tooling — a manual backup is one that eventually gets skipped — and restore drills turn recovery time into a measured figure.

3-2-1 · Checksums · Restore drills · RPO / RTO

The three numbers that decide intelligibility

Every finished call leaves a call detail record, written whether it succeeded or failed. Packet loss, jitter and latency decide whether a call is intelligible — and because codecs conceal small amounts of all three, a call often sounds acceptable on numbers that look alarming.

Discovery from the wire, not from guesswork

CDP and LLDP let devices announce themselves to directly connected neighbours, so one query returns what is physically attached to a port. Combining that neighbour table with interface addresses is what separates a genuine link from two devices sharing a segment.
